# Divine Coliseum — Step 0

Minimal Godot 4.x project foundation. No gameplay systems are implemented.

## Open and test

1. Open Godot 4.x Project Manager, click Import, and select this folder's project.godot.
2. Open the project. No manual Autoload or Main Scene setup is required.
3. Press F6 with scenes/arena/arena.tscn open to preview the standalone arena, then F8 to stop.
4. Press F5 (Run Project). Expect a dark background and a centered gray rectangular arena with a thick wall and light inner border. No units, cards, or gameplay should appear.
5. Resize the game window. The arena should remain centered and proportional. Non-16:9 windows should show letterboxing or pillarboxing.
6. Check the Debugger: expect 0 errors. Press F8 to stop.
7. In Project Settings > Globals > Autoload, confirm GameManager points to res://autoload/game_manager.gd and is enabled. It is already configured; do not add a duplicate. In older Godot 4 versions, Autoload may be its own tab.

## Files created

- project.godot: project name, startup scene, GameManager autoload, Compatibility renderer, dark background, 1920 x 1080 base viewport, and 1280 x 720 initial desktop window.
- scenes/main/main.tscn: Main Node2D instantiating Arena.
- scenes/arena/arena.tscn: Arena Node2D with a fixed Camera2D centered at the origin.
- scenes/arena/arena.gd: typed placeholder rectangle drawing, visible in the editor as well as at runtime.
- autoload/game_manager.gd: empty Node foundation for future global state.
- .gitignore: excludes Godot's generated .godot cache.
- README.md: setup, file descriptions, testing, and limitations.
- autoload/game_manager.gd.uid and scenes/arena/arena.gd.uid: stable script identifiers generated by Godot 4.6.2.

Files modified: none; this is a new project.

Requested scene, resource, art, audio, and script directories are included. Unused directories are empty. Git does not track empty directories; the supplied ZIP preserves them.

## Display decisions

Canvas Items stretch with Keep aspect preserves the 16:9 composition across desktop window sizes. Nearest texture filtering is configured for future pixel assets. Final pixel-art resolution and scaling can be decided when real art is introduced.

Reference: https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html

## Validation and limitations

Godot 4.6.2 Mono completed headless editor import and a five-frame startup with exit code 0 and no GDScript or scene-loading errors. The sandbox blocked the engine's application-data directory and Mono editor socket, and the engine reported a macOS certificate initialization error. Therefore a completely clean debugger run and visual window verification remain manual checks using the instructions above.

The arena is only geometric placeholder art. The camera is stationary. GameManager contains no state or behavior. No Step 1 work is included.
